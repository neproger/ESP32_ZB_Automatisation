# Плата GUITION JC4880P443C_I_W

> Справочник по железу, на котором работает `ha_p4`. Карта системы —
> `../ARCHITECTURE.md`. Здесь: характеристики, распиновка, возможности и процедуры,
> привязанные именно к этой плате. О том, как система их использует, рассказывают
> layer-документы (`../services/ZIGBEE.md`, `../clients/DISPLAY.md`).
> исходники - https://github.com/ultramcu/guition-jc4880p4-bsp/tree/main/examples
## 1. Что это

**GUITION JC4880P443C_I_W** — панель HMI на модуле **JC-ESP32P4-M3-C6**: два чипа
на одной плате плюс дисплей.

```text
ESP32-P4  — основной: дисплей, PSRAM, USB, GPIO, вычисления
   │
   ├── MIPI-DSI  → 4.3" IPS 480x800 + тач GT911 + аудиокодек ES8311
   ├── microSD / MIPI-CSI камера / RS-485 / GPIO 26-pin
   │
   ├── spinel-UART (JP1)  ──  ESP32-C6  — 802.15.4 (Zigbee RCP)
   └── ESP-Hosted SPI     ──  ESP32-C3  — Wi-Fi STA
```

Ключевое для проекта: у **P4 нет своего радио**. Zigbee живёт на **встроенном C6**,
который отдаёт 802.15.4 хосту как **standalone RCP** (`ot_rcp`) прямо по
**spinel-UART**; `esp_hosted` для Zigbee не нужен (`../services/ZIGBEE.md` §5). Wi-Fi
вынесен на **отдельный ESP32-C3** через `ESP-Hosted` (транспорт SPI): coex
Wi-Fi↔802.15.4 на одном C6 нестабилен, см. §4.5. C6 — не самостоятельный узел с
собственным USB: оба USB-порта платы принадлежат P4.

## 2. Характеристики

### 2.1. ESP32-P4 (основной)

| Параметр | Значение |
|---|---|
| Ядро | 2× RISC-V HP @ до 400 МГц + LP-ядро @ 40 МГц |
| PSRAM | 32 МБ |
| Внутренняя память | 768 КБ L2MEM, 32 КБ LP SRAM, TCM |
| Ускорители | 2D-графика (PPA), H.264 и JPEG |
| Радио | нет |
| USB | 2× USB 2.0 (full-speed + high-speed native) |
| Security | secure boot, flash encryption, ключи/подпись |

**Ревизия и частота.** Плата идёт с P4 rev < 3.0, для неё 400 МГц недоступна
(`esp_clk_init` assert). Проект выбирает ревизию явно и работает на **360 МГц**
(`sdkconfig.defaults:5-10`).

### 2.2. ESP32-C6 (радио)

| Параметр | Значение |
|---|---|
| Wi-Fi | Wi-Fi 6 (802.11ax), 2.4 ГГц |
| Bluetooth | Bluetooth 5 (LE) |
| 802.15.4 | Zigbee / Thread |
| Flash | 4 МБ (модуль `ESP32-C6-MINI-1U-N4`) |
| Антенна | IPEX + керамическая |

### 2.3. Дисплей, тач, звук

| Параметр | Значение |
|---|---|
| Дисплей | 4.3", IPS, 480×800, драйвер ST7701, интерфейс MIPI-DSI (2 lane) |
| Тач | Goodix GT911, ёмкостный, I2C addr `0x5D`/`0x14` |
| Кодек | ES8311 + микрофон и динамик |

## 3. Возможности и интерфейсы

- 2× USB Type-C (см. §5);
- GPIO: гребёнка 26 контактов (2.54 мм) — I2C, SPI, PWM, ADC, RMT, MCPWM, TWAI (CAN),
  LEDC;
- UART0 и дополнительный UART (MX 1.25 4P), RS-485 (MX 1.25 4P);
- MIPI-CSI — камера (FPC);
- microSD;
- питание: USB-C или литиевый аккумулятор (MX 1.25 2P);
- габариты платы 114.4 × 66.8 мм, рабочий диапазон −20…+70 °C.

## 4. Распиновка связей

### 4.1. P4 ↔ C6: spinel-UART (802.15.4 RCP)

C6 несёт только 802.15.4 и отдаёт его хосту прямо по UART; `esp_hosted` не
используется. На P4 стек Zigbee идёт в режиме `ESP_ZIGBEE_RADIO_MODE_UART_RCP`
(`zigbee/src/zigbee_radio.c`), C6 прошит штатным `ot_rcp`. Пины и скорость — §4.2.

Линии SDIO между P4 и C6 (P4 `SDIO_D0…D3` = 14…17, `SDIO_CLK` 18, `SDIO_CMD` 19,
`C6_RESET` 54) на модуле разведены, но текущей прошивкой не используются: пресет
платы (`CONFIG_ESP_HOSTED_P4_DEV_BOARD_FUNC_BOARD`) в `sdkconfig.defaults` отключён.

### 4.2. Spinel-UART между P4 и C6

Данные радио (`spinel`) идут отдельным UART. **На этой плате он не распаян** — нужны
перемычки на гребёнке **JP1**:

```text
GPIO29 (TX) ── C6_U0RXD (C6 GPIO17)
GPIO30 (RX) ── C6_U0TXD (C6 GPIO16)
GND         ── GND
```

Скорость `460800`, порт `UART1` (`zigbee/src/zigbee_radio.c:50-53`).

Линии JP1 приходят на `UART0` C6 (`U0RXD` GPIO17 / `U0TXD` GPIO16) — это штатный
spinel-UART прошивки `ot_rcp`. `GPIO20/21` C6 (штатный `UART1`) отданы линиям SDIO
модуля (`D0/D1`, §4.1).

### 4.3. Общая шина I2C (тач и аудио)

| Устройство | Адрес | Линии |
|---|---|---|
| Тач GT911 | `0x5D`/`0x14` | SDA = GPIO7, SCL = GPIO8 |
| Кодек ES8311 | `0x18` | SDA = GPIO7, SCL = GPIO8 |

Тач: RST = **GPIO3**, INT = не подключён (управление опросом, `int_gpio_num = -1`).
(Проверено на железе по BSP `ultramcu/guition-jc4880p4-bsp`; ранее в доке ошибочно
указывались RST=22/INT=21.)
Аудио (I2S): MCLK = GPIO13, WS = GPIO10, BCLK = GPIO12, DIN = GPIO48, DOUT = GPIO9,
PA enable = GPIO11.

### 4.4. Дисплей (MIPI-DSI)

2 data lane @ 500 Мбит, `RGB565`, DPI clock **34 МГц**, PHY LDO канал 3 (2500 мВ).
Тайминги 480×800 (проверено): HSW 12 / HBP 42 / HFP 42, VSW 2 / VBP 8 / VFP 166.
Panel reset = GPIO5, подсветка = **GPIO23** (LEDC PWM, питает boost MP3202).
Init ST7701 — `display_p4/src/st7701_init.h` (шлётся вручную через `tx_param`).

### 4.5. Внешний ESP32-C3: Wi-Fi (ESP-Hosted по SPI)

Встроенный C6 занят 802.15.4 (Zigbee/ot_rcp), а coex Wi-Fi↔802.15.4 на одном C6
нестабилен: скан Wi-Fi при активном RCP возвращает 0 AP. Поэтому Wi-Fi вынесен на
**отдельный ESP32-C3** (`ESP-Hosted` 3.0.9). Транспорт — **SPI full-duplex**: прежний
UART на 115200 был узким местом (не держал высокие скорости), SPI снял это ограничение.

| Сигнал | GPIO P4 (JP1) | GPIO C3 |
|---|---|---|
| SPI CLK | 32 | 6 |
| SPI MOSI | 28 | 7 |
| SPI MISO | 33 | 5 |
| SPI CS | 31 | 10 |
| HANDSHAKE (CP→P4) | 49 | 4 |
| DATA_READY (CP→P4) | 50 | 3 |
| Reset CP (EN) | 34 | EN (кнопка RST) |
| GND | GND | GND |
| Питание | 5V | 5V |

- **Режим SPI = 3** на обоих концах (CP-дефолт); mode в Kconfig хоста
  (`CONFIG_ESP_HOSTED_HOST_SPI_MODE=3`). Частота — **`40` МГц**
  (`CONFIG_ESP_HOSTED_HOST_SPI_CLK_MHZ`, потолок для C3-цели); проверено на разводке,
  при сбоях на длинных проводах — снижать (26 и т.п.).
- Пины P4 — с гребёнки **JP1** (все шесть выведены): 32/28 — бывшие UART, 34 — reset;
  31/33/49/50 — свободные GPIO гребёнки. На C3 свободны `0..10,18..21` (11–17 flash);
  выбраны без strapping (`2/8/9`) и USB-пинов.
- Очереди SPI хоста подняты до 24 (`CONFIG_ESP_HOSTED_HOST_SPI_{TX,RX}_Q_SIZE`), на CP 20;
  LVGL-задача прибита к **ядру 1** (`display_p4`), esp_hosted остаётся на ядре 0.
- **Питание C3 — лучше отдельное** (с P4 делить только GND): высокоскоростной линк
  чувствителен к просадкам 5V при пере-энумерации P4 (в т.ч. при выборе COM-порта в IDE —
  дёргаются DTR/RTS). Чтение консоли C3 (COM9) — с `DTR`/`RTS` = false.
- Прошивка CP (транспорт/пины) — во внешнем проекте `esp_hosted_c3_cp` (не в git); держать
  синхронно с хостом (`CONFIG_EH_TRANSPORT_CP_SPI*` = пинам/режиму `...HOST_SPI*`).
- **Reset обязателен.** CP отдаёт caps один раз при старте; без сброса хост поднимает
  транспорт позже и теряет handshake (гонка загрузки). Хост дёргает `GPIO34`
  (HIGH→LOW→HIGH на EN) перед ожиданием: `CONFIG_ESP_HOSTED_HOST_RESET_GPIO=34`.
- Цель CP — `CONFIG_SLAVE_IDF_TARGET_ESP32C3=y` (`sdkconfig.defaults`), иначе хост
  ждёт C6 (`0x0d`) и падает на `chip mismatch: expect=0x0d got=0x05`.

## 5. USB на плате

У C6 **нет своего USB**: оба Type-C выведены с P4.

| Порт | Тип | Назначение |
|---|---|---|
| USB1 | full-speed | UART0 P4 через мост CH340C — это порт прошивки и монитора P4 |
| USB3 | high-speed | нативный USB P4 (`ESP_USB_P/N`) |

Отсюда следствие для §6: до C6 снаружи можно добраться **только** через JP1, а не через
USB.

## 6. Прошивка C6 (RCP)

### 6.1. Зачем и что́ шьётся

Заводская прошивка C6 — **ESP-Hosted slave 2.x без RCP** (хост видит
`coprocessor=2.3.2`), поэтому P4 получает `RCP on the co-processor not started`.
Нужна прошивка **standalone 802.15.4 RCP** (`ot_rcp`): P4 соединяется с ней прямо по
spinel-UART, без `esp_hosted`. Wi-Fi на C6 не используется — он вынесен на отдельный
C3 (§4.5).

Исходник — штатный пример `ot_rcp` из ESP-IDF (`examples/openthread/ot_rcp`) для
`esp32c6`; собирать его нужно **вне** `managed_components` (во временной папке), иначе
ломается component manager проекта. Результат — `esp_ot_rcp.bin`.

**UART.** Штатный `ot_rcp` отдаёт spinel на `UART0` на `460800`; на C6 это `U0TXD`
GPIO16 / `U0RXD` GPIO17 — те же линии, что заведены на JP1 (§4.2). Консоль C6 на этот
UART не выводится, иначе делила бы его со spinel.

### 6.2. Подготовка

- Внешний **USB-TTL на 3.3 В** (у C6 нет собственного USB).
- Подключение к гребёнке **JP1**: `C6_U0RXD`, `C6_U0TXD`, `GND`, `C6_IO9` (BOOT),
  `C6_CHIP_PU` (reset).

### 6.3. Порядок

```text
1) припарковать P4 (чтобы его стек Zigbee не слал spinel-кадры в C6 во время записи):
   esptool --chip esp32p4 -p COM4 --before default_reset --after no_reset flash_id

2) прошить C6 (COMx — порт USB-TTL):
   esptool --chip esp32c6 -p COMx -b 460800 --before default_reset --after hard_reset ^
     write_flash --flash-mode dio --flash-size 4MB --flash-freq 80m ^
     0x0 bootloader.bin 0x8000 partition-table.bin 0x10000 esp_ot_rcp.bin

3) вернуть P4:
   esptool --chip esp32p4 -p COM4 --after hard_reset flash_id
```

Если у USB-TTL не разведены DTR/RTS, вход в boot вручную: `C6_IO9` на GND и импульс
`C6_CHIP_PU` на GND.

UART spinel на CP — `UART0 TX16/RX17 460800`; совпадает с хостом (`TX29/RX30 460800`,
§4.2).

### 6.4. Проверка

После прошивки P4 должен поднять RCP и напечатать `bootstrap done`; отсутствие
сообщения означает, что радио не поднялось (`../services/ZIGBEE.md` §5).

## 6.5. Прошивка внешнего C3 (Wi-Fi CP)

Прошивка C3 — пример `esp_hosted` (MCU Wi-Fi), цель `esp32c3`, собирается вне
`managed_components` (во временной папке). Ключевые отличия `sdkconfig.defaults`:

```text
CONFIG_EH_TRANSPORT_CP_SPI=y
CONFIG_EH_TRANSPORT_CP_SPI_HSPI_GPIO_CLK=6
CONFIG_EH_TRANSPORT_CP_SPI_HSPI_GPIO_MOSI=7
CONFIG_EH_TRANSPORT_CP_SPI_HSPI_GPIO_MISO=5
CONFIG_EH_TRANSPORT_CP_SPI_HSPI_GPIO_CS=10
CONFIG_EH_TRANSPORT_CP_SPI_GPIO_HANDSHAKE=4
CONFIG_EH_TRANSPORT_CP_SPI_GPIO_DATA_READY=3
# mode 3 и checksum — дефолты CP
```

Прошивка на COM9 (USB C3) как обычный esp32c3-проект. Консоль C3 — UART0.
