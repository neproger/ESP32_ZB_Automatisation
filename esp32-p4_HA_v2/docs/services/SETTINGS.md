# Settings

Слой: **Services / Settings** — данные; отдельного runtime-сервиса нет. Карта системы —
`../ARCHITECTURE.md`.

## 1. Роль

Настройки приложения — **одна запись** в Domain: `HA_ENTITY_SETTINGS`, форма
`ha_model/ha_settings.h`, ключ `HA_SETTINGS_ID` (0). Регистрирует bootstrap
(`../RECORD_MODEL.md` §1.1); пишут Web/Display, читают потребители. FLASH — переживают
перезагрузку.

Поля добавляются **вместе с реальным потребителем**, а не заранее (`../../AGENTS.MD`).
Сейчас:

| поле | смысл |
|---|---|
| `screensaver_timeout_ms` | таймаут скринсейвера; 0 — выключен |
| `brightness_pct` | подсветка, 0..100 |
| `palette_id` | тема UI (`ui_palette_id_t`); 0 — Retro |

Единственный потребитель — Display: экран настроек (`clients/DISPLAY.md`, `ui_settings.c`)
читает запись и пишет изменения (подсветка — слайдер, скринсейвер — выпадающий список,
тема — выпадающий список). Смена темы пересобирает дерево экранов (см. DISPLAY §6).
При появлении сервисов (погода и т. п.) их параметры добавляются сюда, а не в отдельные
таблицы.
