# Display

Слой: **Clients / Display**. Карта системы — `../ARCHITECTURE.md`.
Документ описывает контракт и поведение; конкретная реализация — в коде.

## 1. Роль

Display — локальный LVGL-интерфейс устройства. Это **осознанное исключение** из общего
правила подписки на события: обновлять LVGL на каждое событие дорого.

## 2. Контракт

- Display остаётся клиентом Domain и **не** линкуется к хранилищу напрямую.
- Вместо подписки на каждое событие он сам периодически читает нужные entity
  (**прямой polling Domain read API**) — это его быстрый путь.
- Read path остаётся за Domain; наружу типы хранилища не выходят.
- Своей модели данных Display не держит.
