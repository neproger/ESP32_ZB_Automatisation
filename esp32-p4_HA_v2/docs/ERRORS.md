# Модель ошибок

> Единый транспорт ошибок для всех слоёв. Конкретные сигнатуры и коды — в коде
> (`sys/include/sys/sys_error.h`).

## 1. Принцип

```text
Ошибка создаётся слоем, в котором возникла, и сохраняет свою identity при
прохождении через остальные слои. Промежуточный слой не перекодирует ошибку,
если сам не создаёт новую.
```

Ошибка — не результат анализа, а факт о том, кто и что обнаружил. Слой, получивший
ошибку нижележащего слоя, не «понимает» её лучше источника: ему нечего добавить, а
перекодирование только теряет автора.

Второе правило — про Journal:

```text
Journal фиксирует ошибку как факт, но не классифицирует, не преобразует и не
интерпретирует её.
```

## 2. Тип

```c
typedef struct {
    uint16_t layer; /* кто создал ошибку: sys_layer_t */
    uint16_t code;  /* что произошло: sys_code_t */
} sys_error_t;
```

`layer` — происхождение: `MSTORE`, `DOMAIN`, `ZIGBEE`, `AUTOMATION`, `WEB`. Нужно для
диагностики, а не для логики: смысл ошибки определяет `code`.

`code` — **общее пространство для всех слоёв**. `NOT_FOUND` означает одно и то же,
кто бы его ни вернул, поэтому вызывающий сравнивает код, не зная, какой слой его
породил. Коды, уникальные для слоя, занимают диапазон от `SYS_CODE_LAYER_BASE` и
имён не пересекают.

Поля `detail` намеренно нет: ни один producer пока не нуждается в числовом
уточнении (partition/driver code). Появится реальный случай — добавим, но не раньше.

## 3. Как это выглядит в коде

Слой создаёт ошибку у себя:

```c
return sys_error_make(SYS_LAYER_MSTORE, SYS_CODE_CORRUPT);
```

Слой выше распознаёт только ожидаемый outcome, остальное пропускает как есть:

```c
sys_error_t err = mstore_table_slot_find(&table, key, &slot);

if (sys_is(err, SYS_CODE_NOT_FOUND)) {
    /* ожидаемая ветка put: записи ещё нет → allocate */
} else if (sys_failed(err)) {
    entity_op_error(&op, err); /* та же ошибка в Journal */
    return err;                /* и вызывающему */
}
```

Цепочка без перекодирования:

```text
mstore   → { layer=MSTORE, code=CORRUPT }
Entity   → та же ошибка
Journal  → факт с той же ошибкой
Service  → та же ошибка (или своя, если создаёт новую)
```

## 4. Что из этого следует

1. **Нет таблиц соответствия.** `domain_err_from_mstore()` и ей подобные не нужны в
   принципе: перевод `MSTORE_* → DOMAIN_*` был перекодированием внутри транспорта.
2. **Нет классификаторов.** «Журналировать или нет» решает место вызова, а не
   функция над кодом ошибки: ожидаемый код — ветка алгоритма, любой прочий сбой —
   факт и возврат (`domain/JOURNAL.md` §2.1).
3. **Ошибка программирования — не ошибка времени исполнения.** `NULL`, неверный
   размер, неинициализированный Domain — это `assert`/diagnostic на входе операции,
   а не код для транспорта. Внутри операции такие коды невозможны, потому что
   аргументы проверены на входе.
4. **Свой код — только своя ответственность.** Слой создаёт новую ошибку, лишь когда
   она возникла в нём: например, Domain сам отвечает «тип не зарегистрирован».

## 5. Открытые вопросы

1. **Нужен ли `detail`.** Держать в уме для IO/driver-specific кодов, пока ни один
   producer его не требует.
2. **Граница layer-specific кодов.** Первый реальный код уровня Domain (например,
   «executor не найден») покажет, удобен ли общий диапазон от
   `SYS_CODE_LAYER_BASE`.
3. **Представление ошибки наружу.** Web-слой переводит `sys_error_t` в DTO; формат
   пока не определён — ждём потребителя.
